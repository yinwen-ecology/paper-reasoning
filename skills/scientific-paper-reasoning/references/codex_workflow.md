# 在 Codex / GPT-6.1 sol 中完成论文精读

用于需要工具读取、长材料处理或完整文件交付的任务。科学判断与六拍判据见 scientific_reasoning_framework.md；这里处理如何可靠拿到证据、组织上下文并交付可读成稿。

## 先确认材料能回答什么

本地全文先读已有文件。DOI、标题或出版社链接可使用当前可用的论文获取工具；若 paper-fetch-skill 可用，按它的协议确认身份和正文。仅返回元数据、摘要或失败状态时，不能当作已获得全文。可读出版社正文或其他可信全文可补足来源。源文件齐全时不必重新搜索下载。

读正文、图注与关键方法要围绕中心判断。例如森林尺度的主张，应核对森林尺度结果及其统计方法；物种数不能代替该回归的独立样本量。图注缺少坐标、异常点或组间重叠信息时，打开原图或渲染对应 PDF 页。图像判断与文本提取互相补充。

核对少量决定贡献的前序研究，适用于“首次提出”“推翻已有认识”等需要确认的判断。只扩展会改变本篇解释的文献；跨论文背景与本篇直接证据使用各自的来源链接。

## 给长文保留可用的证据记录

长文、补充材料或跨轮任务可在工作目录保存简洁记录：中心主张、相应图表或方法位置、原文报告的数值和单位、作者解释、待核对项。保持原始来源和分析判断可区分。这是继续工作的记忆，不作为读者必须先看的附录。

检索时围绕具体图号、指标或方法读取，减少重复全文回显。相互独立的材料读取可批量执行；核对关键结果后再作依赖它的判断。工具未返回的内容保持待核对，不能由模型记忆补成论文事实。

## 从证据写出读者看得懂的分析

默认读者有科研基础，细分领域术语仍需解释。术语的第一句解释用途，第二句解释数值方向或生态含义；随后给论文中的比较。涉及负水势、差值或比例时，一组明确标为示意的数值往往比抽象定义更有用。

用“元问题 N：完整问题”与“回答：”让读者找到答案。元问题 1–3 分别承担问题、价值和新认识；六拍承担研究前认识如何一步步走到结果与后果。六拍前两拍充分展开，后面的设计应对应前面提出的悬念。

中心统计结果解释三件事即可：比较的单位是什么、结果有多强、它支持哪种判断。例如“在这批样地中，HSM 与净生物量变化的关系最突出”可作为明确判断；候选变量只有一个通过显著性校正，不自动等于模型之间已完成预测优劣比较。把这一具体边界集中写在结果的解释处。

保持判断直接。每段先有实质结论，再解释关键证据；限定范围的词放进结论本身，例如“在所研究样地中”。避免每段末尾补一条通用限制。示意例子、作者事实、推理重建用自然语言说明身份，无需给每句加标签。

## 成稿与核验

完成两次目的明确的通读：第一次沿中心主张回查来源、数值、分析单位和统计含义；第二次跟着读者检查变量解释、推断跳步、问答与六拍的重复。修正发现的问题后交付，不以无限追加检查替代完成。

用户要求 Markdown 时生成实际 UTF-8 文件，公式和链接使用标准 Markdown。既有文件的修订保持同一交付路径，按可用工具在 Codex 中打开。最终回复提供文件链接和影响阅读的主要变化，文件本身应能独立阅读。

Skill 的格式校验只证明文件结构有效。输出能力的评价需要用实际论文检查：读者能否指出核心问题，关键图是否准确，结论是否匹配方法，是否讲清了真正的新认识。单篇案例的改善可证明这次改写有用；稳定的跨领域能力需要不同类型论文的实际使用证据。
